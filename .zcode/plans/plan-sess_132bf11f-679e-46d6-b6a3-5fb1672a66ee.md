# خطة Reconciliation الحسابات المالية — قسم المكتب

## الهدف العام
إعادة بناء أرصدة الخزن والبنوك والمحافظ لقسم المكتب من الـ ledger (`account_entries`)، ومقارنتها بالأرصدة المخزنة في `accounts.balance`، ثم تسجيل الفروقات وإصلاحها بالتدريج خطوة بخطوة.

## الـ Truth Source (المصدر الموثوق للحقيقة)
> **`accounts.balance` يجب أن يساوي `SUM(account_entries.credit) - SUM(account_entries.debit)` لكل account.**

- **الجدول الـ canonical**: `accounts` (الفلتر: `module_type='office'`).
- **العملة**: الأرقام قد تكون بعملات مختلفة (EGP, USD, KWD, ...)، فلازم نقارن كل account بعملته.

## المراحل (مع workflow تدريجي)

### 🔵 المرحلة 0: Reconnaissance — كل الخزن والبنوك والمحافظ في المكتب
**اللي هنعمله دلوقتي** (read-only، آمن 100% على البرودكشن)

**Script جديد**: `scripts/office_liquidity_snapshot.php`

**Logic**:
- Laravel bootstrap (نفس النمط في `scripts/bus_module_full_e2e.php`)
- Query:
  ```sql
  SELECT id, name, type, treasury_type, currency, balance, is_active, created_at
  FROM accounts
  WHERE type IN ('cashbox','bank','wallet','treasury')
    AND module_type = 'office'
    AND deleted_at IS NULL
  ORDER BY type, currency, name;
  ```
- يطبع جدول منسق في الـ terminal بأعمدة: `ID | Name | Type | Currency | Balance | Active | Created`.
- يحفظ JSON snapshot في `storage/logs/office_liquidity_snapshot.json` (للمراحل الجاية).

**مخرجات المرحلة**:
1. Script: `scripts/office_liquidity_snapshot.php`
2. Output في الترمنال: جدول مقروء
3. File: `storage/logs/office_liquidity_snapshot.json` فيه كل الـ accounts + الـ metadata

### 🟢 المرحلة 1: Per-account Ledger Rebuild (بعد موافقة على المرحلة 0)
**Script**: `scripts/office_liquidity_rebuild.php`

**Logic لكل account من snapshot المرحلة 0**:
- يحسب الرصيد الفعلي:
  ```sql
  SELECT COALESCE(SUM(credit),0) - COALESCE(SUM(debit),0) AS computed_balance
  FROM account_entries
  WHERE account_id = ?;
  ```
- يقارنه بـ `accounts.balance` (المخزّن).
- يحسب الـ `drift = stored - computed`.
- يصنّف: `OK` (drift=0)، `DRIFT` (≠ 0)، `NO_ENTRIES` (مفيش ledger entries).

**Output**:
- جدول: `ID | Name | Type | Stored | Computed | Drift | Status`
- يحفظ في `storage/logs/office_liquidity_drift.json`

### 🟡 المرحلة 2: User Review & Decision
- أنا هعرضلك جدول الفروقات وأنت تقرر:
  - نظبط الـ `accounts.balance` ليطابق الـ ledger (writeoff transaction)؟
  - نضيف entries تصحيحية؟
  - نمسح entries خاطئة؟
  - نشوف كل entry لوحده ونفهم السبب؟

### 🔴 المرحلة 3: Apply Corrections (بعد موافقتك)
- **مش هنفّذ أي تعديل في الـ DB قبل موافقتك الصريحة**.
- التعديلات هتكون عن طريق transactions من نوع `writeoff` (للـ audit trail).
- كل تعديل هيتسجل في الـ notes.

### ✅ المرحلة 4: Verification
- إعادة حساب الـ drift، المفروض تكون 0.
- تقرير نهائي: `storage/logs/office_liquidity_reconciliation_report.md`.

### المراحل اللاحقة (بعد ما نخلص الخزن والبنوك والمحافظ)
- **المرحلة 5**: معالجة الـ legacy tables (`treasuries`, `banks`, `wallets`) — لو في data هناك مالهاش mirror في `accounts`.
- **المرحلة 6**: نظبط الديون (customers/suppliers accounts) اللي مرتبطة بالمكتب.
- **المرحلة 7**: الأرباح (Profit accounts) للمكتب.
- **المرحلة 8**: الميزان الحسابي (Trial Balance) — للتأكد إن `SUM(debit) = SUM(credit)` على مستوى النظام كله.

## ⚠️ معايير الأمان
- كل المراحل من 0 إلى 2 **read-only** على البرودكشن.
- أي تعديل في الـ DB (المرحلة 3+) يتطلب موافقة صريحة منك أولاً.
- كل تعديل هيكون في صورة transaction من نوع `writeoff` عشان يبقى في الـ audit trail.
- **مش هنتعامل مع السياحة** (`module_type='tourism'`) في أي مرحلة من دول.

## 📌 اللي محتاج منك دلوقتي
وافق على الـ plan عشان أبدأ بالمرحلة 0 (الـ snapshot).

## ملخص اللي هنعمله في الخطوة الجاية (المرحلة 0)
1. أنشئ `scripts/office_liquidity_snapshot.php` بـ Laravel bootstrap.
2. الـ script يجيب كل `accounts` حيث `type IN ('cashbox','bank','wallet','treasury')` و `module_type='office'`.
3. يطبع جدول منسق في الـ terminal.
4. يحفظ JSON في `storage/logs/office_liquidity_snapshot.json`.
5. مش هيكتب أي حاجة في الـ DB.
6. نشوف النتيجة مع بعض، وبعدين نروح للمرحلة 1.
