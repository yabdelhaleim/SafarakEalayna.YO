## Fix: 404 on "Add Office Wallet" shortcut in WalletCreate.vue

### Root cause (two compounding bugs)

The shortcut link at `resources/js/views/wallet/WalletCreate.vue:261-268` is broken in **two** ways:

1. **Wrong path.** The hard-coded URL is `/admin/accounts/create`. That route does not exist. Filament v3 derives a resource's URL slug from its **resource class name** (not the model) — see `vendor/filament/filament/src/Resources/Resource/Concerns/HasRoutes.php:176-215`. For `App\Filament\Admin\Resources\WalletAccounts\WalletAccountResource` this yields slug `wallet-accounts`, so the real route is `/admin/wallet-accounts/create`. (The only `AccountResource` lives in `FinanceCluster` at `/admin/finance/...`.) The sibling `resources/js/views/flights/FlightCreate.vue:3311` already uses the correct path.
2. **`{{ }}` inside an HTML attribute.** Line 262 places `{{ selectedWalletType?.code }}` inside `href=...`. Vue 3 only interpolates mustaches in text content; attribute values need `v-bind` (or `:` shorthand). All other 8+ references to `selectedWalletType?.code` in the same file are in text content and work; this is the only one in an attribute.

Either bug alone would 404. Together the URL becomes `/admin/accounts/create?type=wallet&module_type=office&wallet_provider={{%20selectedWalletType?.code%20}}`, which is what the screenshot shows.

### Changes

#### 1. `resources/js/views/wallet/WalletCreate.vue`

Add a `computed` URL right after the existing `selectedWalletType` computed (currently at lines 851-855), mirroring the established pattern at `resources/js/views/flights/FlightCreate.vue:3309-3312`:

```js
const newOfficeWalletUrl = computed(() => {
  const code = selectedWalletType.value?.code ?? '';
  return `/admin/wallet-accounts/create?type=wallet&module_type=office&wallet_provider=${code}`;
});
```

Change the link (lines 261-262) from:

```html
<a
  href="/admin/accounts/create?type=wallet&module_type=office&wallet_provider={{ selectedWalletType?.code }}"
  target="_blank"
  ...
```

to:

```html
<a
  :href="newOfficeWalletUrl"
  target="_blank"
  ...
```

This fixes both bugs in one go: correct path and Vue-attribute binding.

#### 2. `app/Filament/Admin/Resources/WalletAccounts/Pages/CreateWalletAccount.php`

Add `mutateFormDataBeforeFill()` to pre-populate the form from URL query params, so the shortcut fully completes the user flow (the page opens with `wallet_provider` and `module_type` already selected). Pattern precedent: the only existing `mutateFormDataBeforeFill` in the codebase is at `app/Filament/Admin/Resources/VisaBookings/Pages/EditVisaBooking.php:72-92` (record-based fill), and `request()->query(...)` is already idiomatic in `app/Filament/Admin/Widgets/FinancialStatsWidget.php:36-37`.

Add two imports at the top:

```php
use App\Enums\WalletProvider;
use App\Support\Finance\AccountModuleDivision;
```

Add the new method (alongside the existing `mutateFormDataBeforeCreate`):

```php
/**
 * Pre-fill wallet_provider and module_type from URL query string
 * when arriving from a shortcut link (e.g. WalletCreate.vue).
 *
 * Validates against the canonical enum/options lists so a tampered URL
 * cannot inject arbitrary values.
 */
protected function mutateFormDataBeforeFill(array $data): array
{
    $provider = request()->query('wallet_provider');
    if (is_string($provider) && array_key_exists($provider, WalletProvider::optionsForSelect())) {
        $data['wallet_provider'] = $provider;
    }

    $moduleType = request()->query('module_type');
    if (is_string($moduleType) && in_array($moduleType, array_keys(AccountModuleDivision::moduleTypeOptions()), true)) {
        $data['module_type'] = $moduleType;
    }

    return $data;
}
```

Notes:
- The existing `mutateFormDataBeforeCreate()` stays as-is. It already sets `type` correctly, and although `AccountFormSchema.php:70-74` makes `type` a `Hidden` with the same default when `$fixedType === AccountType::Wallet`, leaving the method untouched keeps the change minimal and avoids surprising anyone.
- `type` is **not** read from the URL — the Filament form already fixes it via `Hidden` default, and the URL's `type=wallet` is redundant safety only.
- `module` (the legacy singular column) auto-syncs from `module_type` via the `afterStateUpdated` closure at `AccountFormSchema.php:115-119`, so we only need to set `module_type`.
- The `module_type=office` value is one of the 10 canonical values in `AccountModuleDivision::moduleTypeOptions()` and is already what every other wallet/bank/cashbox resource hard-codes (e.g. `CreateBusWallet.php:15`, `CreateVisaWallet.php:13`, `ManageOfficeWallets.php:15-21`), so this is consistent with the existing convention.
