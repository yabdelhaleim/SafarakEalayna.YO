# Tourism Employee Refund Implementation Plan

## Verdict
**GO_WITH_WARNINGS → GO** (after implementation): All audit requirements met, employee refund flows safely gated, full audit trail persisted, admin protections preserved.

---

## Overview
Implement Employee Refund capability for Tourism division (Flight, Hajj/Umrah, Visa) with a new `manage_refunds` permission and dual-write audit trail. Keep all admin-only operations (cancel, delete, confirm, recharge, airline-accounts CRUD) restricted to admin.

## Architectural Decisions (per user answers)
- **Audit persistence**: New `refund_audit_logs` table (specific columns) + row in existing `audit_logs` (action='refund.processed'). Dual-write.
- **Existing tests**: Update `test_employee_cannot_refund_booking` to use `restrictedEmployee` (no `manage_refunds`) → 403. Add new positive tests for `normalEmployee` (has `manage_refunds`) → 201.

## Phase 4: Routes (the critical authorization changes)

**File: `routes/api.php`**

### Flight (lines 229-236) — SPLIT into employee-allowed + admin-only
```php
// Read endpoints — any auth user
Route::get('/treasuries', [RefundController::class, 'treasuries']);
Route::get('/airline-credits', [RefundController::class, 'airlineCredits']);
Route::get('/{id}', [RefundController::class, 'show']);

// Employee-allowed (create + process refund)
Route::middleware('permission:manage_refunds')->group(function () {
    Route::post('/', [RefundController::class, 'store']);
    Route::post('/{id}/process', [RefundController::class, 'process']);
});

// Admin-only — refund reversal (preserve EMP-F-006)
Route::middleware('admin')->group(function () {
    Route::delete('/{id}', [RefundController::class, 'destroy']);
});
```

## Phase 6: RefundAuditLogger Service (new)

**File: `app/Services/Finance/RefundAuditLogger.php` (new)**

Single static-or-injected helper:
```php
public static function logRefund(array $params): RefundAuditLog
{
    // params: user_id, module, booking_id, booking_reference, customer_id,
    //         customer_name, refund_amount, currency, paid_amount_before,
    //         previously_refunded, remaining_refundable, reason,
    //         transaction_id, account_entry_ids, affected_account_id,
    //         idempotency_key
    // ALSO insert into audit_logs (action='refund.processed')
    // Returns the RefundAuditLog instance
}
```

Catches any DB error inside the helper so it never fails the caller (the actual refund succeeded — audit write failure shouldn't roll back the user's refund).

## Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Migration fails on existing duplicate idempotency keys | Pre-flight SELECT in migration like D3 pattern |
| Existing 97 tests break because employees can now refund | Update those 3 tests to use `restrictedEmployee` |
| Frontend RefundWizard breaks on Flight refund | No changes to FlightShow.vue — just adds idempotency_key |
| Auth:id() returns null in tests | Existing fallback `?: 1` pattern preserved |
| RefundAuditLogger failure rolls back the refund | Wrapped in try/catch, logs error, never throws to caller |
| Race condition on idempotency check | UNIQUE DB constraint as defense-in-depth (last-line) |
