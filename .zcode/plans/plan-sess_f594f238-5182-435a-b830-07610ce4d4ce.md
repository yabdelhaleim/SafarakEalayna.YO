### Phase 1: Bookings Lifecycle E2E Audit (4 hours)
**الهدف**: اختبار 12 سيناريو حقيقي على bookings CRUD

#### الـ Scenarios الكاملة:

**1. Create Booking (POST /flight/bookings)** — 5 cases:
- 1a: EGP booking, single passenger, with PNR, cash payment
- 1b: KWD booking, multi-passenger, credit (no payment)
- 1c: Without PNR (should work)
- 1d: With negative purchase_price (must fail with proper error)
- 1e: With selling_price=0 (edge case)

**2. List Bookings (GET /flight/bookings)** — 4 cases:
- 2a: Empty result (no bookings)
- 2b: Filtered by status=CONFIRMED
- 2c: Filtered by currency=KWD
- 2d: Cache key separation (2 users get different cached results)

**3. Show Booking (GET /flight/bookings/{id})** — 3 cases:
- 3a: Existing booking (200 with full payload)
- 3b: Soft-deleted booking (404 or withTrashed behavior?)
- 3c: Non-existent ID (404)

**4. Confirm Booking (POST /flight/bookings/{id}/confirm)** — 3 cases:
- 4a: From PENDING → CONFIRMED
- 4b: From CONFIRMED (must fail)
- 4c: From CANCELLED (must fail)

**5. Add Payment (POST /flight/bookings/{id}/payments)** — 6 cases:
- 5a: Normal EGP payment
- 5b: Partial payment (multiple times)
- 5c: Overpayment (exceeds selling_price)
- 5d: With idempotency_key replay (returns existing payment)
- 5e: Currency mismatch (EGP booking + KWD payment handling)
- 5f: Idempotency key after soft-delete (Bug #1 check)

**6. Cancel Booking (POST /flight/bookings/{id}/cancel)** — 4 cases:
- 6a: No payments yet
- 6b: With partial payments (reversal check)
- 6c: With full payments (full reversal check)
- 6d: From REFUNDED status (must fail)

**7. Delete Booking (DELETE /flight/bookings/{id})** — 4 cases:
- 7a: Booking with no payments (full reversal check)
- 7b: Booking with partial payments
- 7c: Booking with refund (reverse refund too)
- 7d: Already deleted (idempotent behavior)

**8. Send Ticket Email (POST /flight/bookings/{id}/send-ticket-email)** — 3 cases:
- 8a: With valid PNR
- 8b: Without PNR (should it work?)
- 8c: Invalid email address

**Total: 32 test cases** covering ~5 ops × multiple scenarios

### الـ Test File Template (for reference)

```php
<?php

namespace Tests\Feature\Flight;

use Tests\TestCase;
use Illuminate\Foundation\Testing\RefreshDatabase;

class BookingLifecycleAuditTest extends TestCase
{
    use RefreshDatabase;

    /**
     * 1a: Create EGP booking, single passenger, with PNR
     */
    public function test_create_egp_booking_with_pnr(): void
    {
        // Setup
        $customer = $this->createCustomer();
        $carrier = $this->createCarrier(['currency' => 'EGP']);
        $system = $this->createSystem();

        // Action
        $response = $this->postJson('/api/v1/flight/bookings', [
            'customer_id' => $customer->id,
            'flight_carrier_id' => $carrier->id,
            'flight_system_id' => $system->id,
            'currency' => 'EGP',
            'selling_price' => 5000,
            'purchase_price' => 4500,
            'pnr' => 'ABC123',
            'passengers' => [
                ['name' => 'John Doe', 'passport' => 'A1234567']
            ],
        ]);

        // Assertions
        $response->assertStatus(201);
        $response->assertJsonStructure(['data' => ['id', 'pnr', 'status']]);
        $this->assertDatabaseHas('flight_bookings', ['pnr' => 'ABC123']);
    }

    // ... 31 more test cases
}
```
