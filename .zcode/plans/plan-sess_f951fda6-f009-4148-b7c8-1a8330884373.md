## Phase Plan — Visa (Phases 9.0 through 9.14)

Each phase produces a discrete, committable deliverable. Per-phase commit + per-phase report (`docs/PHASE_9_X_REPORT.md`).

### Phase 9.0 — Pre-flight + Baseline (no new test code)
- Verify `APP_ENV`, `DB_DATABASE`, branch, commit, PHP version, Laravel version.
- Run `phpunit.xml` against `safarakealayna` (read-only) to capture baseline: 329 pass / 16 fail / 0 skip (Visa).
- Classify the 16 pre-existing failures from `docs/PHASE_8_5_BACKLOG_REPORT.md` §3 as **Class-D (Deferred)** so they don't pollute new findings.
- Snapshot financial totals: `account_balance_sum`, `credits_sum`, `debits_sum` on `safarakealayna` (read-only).
- Create branch `phase-9-tourism-production-audit-visa`.
- Create `tests/Stress/Visa/` tree.
- Create `docs/PHASE_9_0_BASELINE_REPORT.md`.

### Phase 9.1 — Master Data Audit (Section 4)
- File: `tests/Feature/Visa/VisaMasterDataAuditTest.php` (~10 tests)
- Coverage: status enum completeness, agent deactivation impact, duration validity, visa_type completeness, currency coverage, settings endpoint contracts.
- **Reference:** `VisaTestCase` (already seeds master data).

### Phase 9.2 — Admin E2E (Section 6)
- File: `tests/Feature/Visa/VisaAdminFullLifecycleTest.php` (~20 tests)
- New file: `tests/scripts/stress_visa_admin_e2e.php` (16-scenario expansion of `visa_full_module_e2e.php`)
- Adds the gaps: multi-payment across methods (cash + bank + wallet on same booking), Submitted→UnderReview→Approved→Issued lifecycle.
- Builds on `VisaTestCase` + `visa_full_module_e2e.php`.

### Phase 9.3 — User E2E (Section 7) — **TOP PRIORITY GAP**
- File: `tests/Feature/Visa/VisaEmployeeFullLifecycleTest.php` (~18 tests)
- This is the **only** missing E2E persona. Mirrors `VisaProductionE2ETest` but driven by `employeeUser` from `VisaTestCase:115-119`.
- Asserts: employee CAN `addPayment`, CAN `refund` (with `manage_refunds`), CANNOT `cancel`, CANNOT `delete`, CANNOT `pay-customer-debt`, CANNOT `withdraw-from-agent`.
- Pattern: `tests/Feature/Security/AuthorizationGatesTest.php:67-89` for multi-user setup.

### Phase 9.4 — Refund Deep Audit (Section 8)
- File: `tests/Feature/Visa/VisaRefundDeepAuditTest.php` (~15 tests)
- New file: `tests/scripts/stress_visa_refund_attack.php` (100 concurrent refund attempts, curl_multi)
- Closes gaps: partial refund of arbitrary amount (not just 100%), refund > paid (must REJECT), refund after partial refund, refund with multi-currency, 3x double-refund.

### Phase 9.5 — Cancel Deep Audit (Section 9)
- File: `tests/Feature/Visa/VisaCancelDeepAuditTest.php` (~12 tests)
- Closes gap: **agent AP balance after CANCEL** (only soft-delete is currently tested). Add `test_cancel_restores_agent_ap_balance`.

### Phase 9.6 — Delete/Reverse Deep Audit (Section 10)
- File: `tests/Feature/Visa/VisaDeleteDeepAuditTest.php` (~12 tests)
- New file: `tests/scripts/stress_visa_delete.php` (concurrent delete attempts)
- Asserts: zero ghost income, zero ghost expense, zero ghost payment, zero ghost ledger entry, zero ghost supplier debt.

### Phase 9.7 — Financial Accounting + Ledger Reconciliation (Sections 11–13)
- File: `tests/Feature/Visa/VisaFinancialReconciliationTest.php` (~22 tests)
- Per-booking independent calc: `Purchase`, `Selling`, `Customer Paid`, `Customer Outstanding`, `Supplier Payable`, `Supplier Paid`, `Profit`, `Refunded`, `Net Revenue`.
- `assertLedgerGloballyBalanced` after every multi-booking fixture set.
- Supplier AP balance under multi-booking scenarios (new — gap).
- Multi-currency module/related_type tags verification.

### Phase 9.8 — Idempotency Deep (Section 14) — **Includes fix of known defect**
- File: `tests/Feature/Visa/VisaIdempotencyDeepTest.php` (~12 tests)
- **Source code change** (1 commit, user-approvable):
  - Add migration: `2026_08_19_xxxxxx_add_unique_constraint_to_visa_payments_reference.php` — UNIQUE on `visa_payments(booking_id, reference)`.
  - Add migration: `2026_08_19_xxxxxx_add_idempotency_key_to_visa_payments.php` — `idempotency_key` column with UNIQUE index.
  - Update `VisaBookingService::addPayment()` to: check `idempotency_key` first, return existing transaction on match; fall back to `(booking_id, reference)` unique constraint.
  - Update `Visa\AddPaymentRequest` (or equivalent FormRequest) to accept optional `idempotency_key`.
- Audit then verifies: same key → one effect; same booking+ref → DB rejects; different keys + same payment → service-layer dedup.

### Phase 9.9 — TRUE HTTP Concurrency (Sections 15–17)
- File: `tests/scripts/stress_visa_concurrent_payments.php` (10x + 25x, curl_multi)
- File: `tests/scripts/stress_visa_hot_booking.php` (100 concurrent ops on same booking)
- File: `tests/scripts/stress_visa_hot_supplier.php` (100 concurrent ops on same agent)
- File: `tests/scripts/stress_visa_concurrent_cancels.php` (parallel cancel + payment race)
- Pattern: `tests/scripts/bus_deep_concurrency_e2e.php:83-121` (`parallelHttpPosts`)
- Use `safarak_stress` MySQL + port 18000.
- Output: PASS/FAIL counts, race condition evidence, deadlock count.

### Phase 9.10 — Failure Injection (Section 18)
- File: `tests/Feature/Visa/VisaTransportFailureTest.php` (~12 tests)
- Uses `Http::fake([...])` for upstream 502/timeout; `Bus::fake()` for queue failures; `DB::transaction` + throw to simulate mid-transaction failure.
- Asserts **ALL-OR-NOTHING** rollback for each failure injection point.

### Phase 9.11 — Validation + Auth/IDOR (Sections 19–21)
- File: `tests/Feature/Visa/VisaIDORTest.php` (~12 tests) — **object-level cross-user access**.
- File: `tests/Feature/Visa/VisaSensitiveEndpointAuditTest.php` (~6 tests) — audit log of read access.
- Extends `VisaValidationTest` (already 30 tests) for: unicode normalization, emoji in numeric fields, MySQL max packet size, sequential ID enumeration.

### Phase 9.12 — Supplier Flow Deep (Section 22)
- File: `tests/Feature/Visa/VisaSupplierFlowDeepTest.php` (~12 tests)
- Withdraw → repay cycle integrity; agent AP balance after cancel; agent deactivation behavior; office-division rejection; inactive-agent booking rejection.

### Phase 9.13 — State Machine Matrix (Section 23)
- File: `tests/Feature/Visa/VisaStateMachineMatrixTest.php` (~30 tests)
- Full transition matrix: `Draft / Submitted / UnderReview / Approved / Issued / Rejected / Cancelled / Refunded / Deleted`.
- Legal transitions: Submitted→UnderReview, UnderReview→Approved, Approved→Issued, any→Cancelled (pre-pay), any→Refunded (post-pay).
- Illegal transitions (must REJECT): Cancelled→Submitted, Refunded→Approved, Deleted→Refunded, Refunded→Cancelled, Issued→Cancelled (post-pay), etc.

### Phase 9.14 — Final Verdict + Report (Sections 24–30)
- Aggregates all 13 prior phase reports.
- Executes a final independent reconciliation across all 9.x test bookings.
- File: `docs/PHASE_9_VISA_FINAL_REPORT.md` with:
  - Executive Summary (per-area PASS/FAIL)
  - Test Statistics
  - Defect Matrix (Class-A/B/C/D with file:line refs)
  - Financial Reconciliation (per-account, per-currency, per-module)
  - Concurrency Results (10x, 25x, hot-booking, hot-supplier)
  - Authorization Results (admin, user, cross-user, IDOR, sensitive endpoints)
  - Final Verdict: 🟢 GO / 🟡 CONDITIONAL GO / 🔴 NO-GO
