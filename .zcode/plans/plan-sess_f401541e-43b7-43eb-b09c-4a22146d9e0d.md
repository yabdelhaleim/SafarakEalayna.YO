# PHASE 10: Comprehensive Bus Module E2E Test — Plan

## Goal
Create **one** self-contained PHP script that exercises **~50 scenarios** across the entire Bus module (CRUD + Payments + Cancellation + Deletion + Debt/Debtor + Filament UI + Model Guards + Ledger Integrity) and outputs a colored PASS/FAIL report — confirming **0 errors** in the accounting flow.

## Approach

Mirror the existing `phase8_bus_deletion_cycle.php` style (idempotent pre-cleanup, global ledger checks, final cleanup), but expanded to cover the full module surface. The script runs via:

```bash
php artisan tinker --execute='require "phase10_bus_full_e2e.php";'
```

### Script structure — 12 sections, ~50 scenarios

| § | Section | # scenarios | What it tests |
|---|---------|-------------|---------------|
| **A** | Setup & pre-cleanup | — | Find-or-create user/accounts/FX/clearing; pre-delete any leftover `PHASE10-*` rows |
| **B** | Booking CRUD | 5 | create EGP, create with auto-customer, list+filter, show, update notes, show trashed |
| **C** | Payment flows | 6 | full pay, partial → top-up, multi-payment (3×), USD FX (50→EGP), Idempotency-Key replay, overpayment rejection |
| **D** | Cancellation | 4 | cancel no-penalty (full cash refund), cancel full-penalty (no refund), cancel partial-penalty, refund-request flow |
| **E** | Simple `deleteBooking` | 2 | succeeds when unpaid, rejects when has payments |
| **F** | `deleteBookingWithReversal` | 6 | partial-paid Δ=0, fully-paid Δ=0, multi-payment Δ=0, USD FX Δ=0, idempotency (2nd call → Arabic error), cancel-already-reversed booking (just hides row) |
| **G** | Inventory debt lifecycle | 5 | Deferred: pay partial, pay full, reject overpay, reject Cash inventory, partial→full then Δ=0 on cashbox |
| **H** | `deleteInventory` | 3 | Cash → reverses expense (Δ=0 on cashbox), Deferred + all-debt-paid (succeeds), reject when bookings exist |
| **I** | Company & statements | 3 | delete empty company, reject delete with inventory, statement endpoint returns balance row |
| **J** | Filament UI render | 6 | `Livewire::test()` on ManageBusBookings, ManageBusInventories, ListBusCompanies, ManageBusTickets, EditBusCompany, InventoriesRelationManager |
| **K** | Filament actions | 4 | payDebt visible on Deferred, hidden on Cash, deleteCompany service-call path, deleteInventory via relation manager |
| **L** | `ModelDeletionGuard` | 4 | each of `BusBooking/BusInventory/BusCompany/BusTicket` throws RuntimeException on direct `->delete()` |
| **M** | Filament wiring integrity | 4 | code-inspect for raw `DeleteAction::make()` / `DeleteBulkAction::make()` in each resource; require `app(BusXxxService::class)->delete*` |
| **N** | Global invariant + cleanup | 2 | `assertLedgerGloballyBalanced()` post-everything; force-delete test rows + reset cashbox |

### Critical contracts pinned by the script
- **Δ = 0** from pre-test baseline for every `deleteBookingWithReversal` path (cashbox, company AP, customer AR, inventory count) — the same contract as Phase 8 but extended to FX + multi-payment + already-cancelled.
- **Customer debt isolation**: when a customer has existing debt from another booking, deleting one booking must NOT touch the other's debt (Scenario F7 — covered by deleting 1 of 2 bookings and verifying the other customer's AR balance is untouched).
- **Inventory debt isolation**: deleting an inventory whose debt was already partially paid must restore `amount_paid`/`remaining_debt` to 0 (Scenario H2).
- **Filament integrity**: every delete path goes through a service — no raw `DeleteAction::make()`/`DeleteBulkAction::make()` anywhere.

### Pre-cleanup strategy (idempotent re-runs)
Tag every test row with `'PHASE10-RUN-<marker>'` in `notes`. On script start, force-delete (via `withoutEvents()` + `forceDelete()` to bypass `SoftDeletes` + `ModelDeletionGuard`) any leftover rows from prior runs.

### Verification gate ("0 errors" verdict)
The script reports **0 failed scenarios** ONLY if all of the following hold:
1. Every test returns `PASS`.
2. `assertLedgerGloballyBalanced()` returns empty imbalanced list at end of every section.
3. Final cashbox balance equals pre-test value after cleanup.

If any test fails, the script prints a detailed failure block (expected vs actual, Δ, file:line context) and `exit(1)`.
