## تشخيص المشكلة (مُحقَّق على اللوكال)

`RefundService::processRefundRequest` و `reverseRefundRequest` (branch=`agency_treasury`) في `app/Services/Flight/RefundService.php` فيها **4 أخطاء محاسبية**:

| # | الفعل الحالي | الأثر |
|---|---|---|
| 1 | `$treasury->credit($refundAmount)` | الخزينة بتزيد بدل ما تقل |
| 2 | `$carrier->debit($refundAmount)` بـ `refund_amount` | الرصيد prepaid بينقص مرتين |
| 3 | لا يوجد عكس GL للبيع | الإيراد لسه على الكتب والربح ما اتمسحش |
| 4 | `recordJournalTransfer(prepaid → cashbox)` | قيد GL غير منطقي (double-count) |

نتيجة التيست التشخيصي (بيع=10000، شراء=8000، ربح=2000، مدفوع كاملاً):
- قبل refund: customer=0, cashbox=+10000, treasury=0, carrier=92000, clearing=-10000 ✓
- بعد refund (الحالي): customer=0, treasury=**+10000**, carrier=**82000**, clearing=**-10000** ❌❌❌
- بعد refund (المفروض): كل الأرصدة ترجع 0/initial

نفس الباترن غلط في `reverseRefundRequest` (refund_amount بدل purchaseNet، قيد GL معكوس).

## الـ Pattern الصحيح (نفس `cancelBooking` + `deleteBookingWithReversal`)

**processRefundRequest** يعمل 3 قيود بالترتيب:
1. **عكس قيد البيع**: `recordJournalTransfer(customer → clearing, amount=refund_amount, related_type=FlightBooking)`
2. **إرجاع تكلفة الشراء** (حسب `purchase_balance_source`):
   - `carrier`: `$carrier->credit(purchaseNet)` + `PrepaidLedgerService::refundCogs('flight_carrier', purchaseNet)`
   - `system`: نفس مع `'flight_system'`
   - `group`: `recordJournalTransfer(expense_contra → group_account, purchaseNet)` ← **GAP: مفقود كلياً**
3. **صرف من الخزينة**: `recordJournalTransfer(cashbox → customer, amount=refund_amount, allow_from_negative=false)` + `TreasuryLedgerMirror::mirrorFlightOutboundFromCash` + TreasuryTransaction بنوع `debit`

**reverseRefundRequest** يعكس الـ 3 خطوات بالظبط:
1. إعادة قيد البيع: `recordJournalTransfer(clearing → customer, refund_amount)`
2. إعادة خصم الوقت: `carrier->debit(purchaseNet)` + `consumeCogs(...)`
3. عكس صرف الخزينة: `recordJournalTransfer(customer → cashbox, refund_amount)`

### Helpers المطلوب تصديرها/إنشاؤها

- `FlightBookingService::purchaseAmountInBalanceCurrency` (private→public static)
- `FlightBookingService::lockedRateFromBookingSnapshot` (private→public)
- `RefundService::resolveCashboxAccount(Treasury, currency, userId)` — جديد

protected function resolveCashboxAccount(Treasury $treasury, string $currency, int $userId): Account {
    $account = Account::where('name', $treasury->name)->first();
    if (! $account) {
        $account = Account::where('type', AccountType::Cashbox->value)
            ->where('currency', $currency)
            ->whereIn('module_type', ['flights', 'tourism'])
            ->first();
    }
    if (! $account) {
        $account = Account::getModuleVault('flights');
    }
    if (! $account) {

            'name' => $treasury->name,
            'type' => AccountType::Cashbox,

            'is_active' => true,
            'owner_type' => 'office',
            'module_type' => 'tourism',
            'created_by' => $userId,

    }
    return $account;
}

## ✅ Acceptance Criteria

1. **Refund كامل (EGP, paid in full):**
   - `customer.account.balance == 0` (±0.01)
   - `cashbox.balance == 0` (±0.01)
   - `treasury.current_balance == 0` (لا تغيير)
   - `carrier.balance == initial_before_booking` (±0.01)
   - `clearing.balance == 0` (±0.01)
   - **Sum of all balance deltas == 0** (الحساب المزدوج محفوظ)

2. **Reverse of refund:** البالانسات ترجع EXACTLY كما كانت قبل الـ refund (delta == 0 لكل حساب).

3. **الدقة الحسابية (zero tolerance):**
   - `customer.balance == max(0, original - total_paid - refund)`
   - `carrier.balance == initial - (purchaseEgp - purchaseNet)`
   - `clearing.balance == -(original - refund)`
   - `sum(all_deltas) == 0.00` بالضبط

4. **كل التيستس الموجودة في `tests/Feature/Flight/` و `tests/Feature/Bus/` تعدي بدون كسر.**

5. **تيست جديد شامل (RefundDiagnosisTest) يمرّ على 4 scenarios.**
